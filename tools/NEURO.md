# Личная нейроротация

Система заменяет прежний путь `AttackAura → Neuro → policy.bin`. Здесь нет готового чужого наведения, воспроизведения трассы или случайного шума. Пока не было обновлений весов, применение запрещено.

## Первая тренировка

1. Запусти клиент из проекта. Локальное окружение `.neuro-runtime` уже подготовлено и проверено на RTX 5050. Для переноса клиента на другой компьютер см. установку ниже.
2. В одиночном мире выбери открытый ровный участок, вид от первого лица. Убери FreeCam и меню, возьми обычное оружие. Боты клиентские: удары регистрируются **локально**, без серверного урона и пакетов атаки по их отрицательным ID.
3. `.neuro bots spawn 1`
4. `.neuro train start personal`
5. Наводись, двигайся, меняй область прицеливания и бей **самостоятельно**. Боевые модули и оба прежних контроллера ротации блокируются. Отсутствие удара, промах и коррекция прицела сохраняются как нормальные демонстрации. Лучше записать несколько минут разнообразного боя, а не только неподвижное сопровождение.
6. `.neuro status`: сначала «Накопление данных», затем «Обучение». Проверяй устройство, число обновлений, ненулевой Δвесов, train/validation и сравнение с baseline. При настройках по умолчанию первые обновления требуют примерно 20–30 секунд непрерывных пригодных данных; меню, смена цели и задержки увеличивают это время.
7. `.neuro train stop`. Дождись завершения сохранения в `.neuro status`.
8. `.neuro model select personal` выбирает и загружает модель. Дождись окончания загрузки по `.neuro status`, затем включи Attack Aura обычным биндом, когда выбран режим ротации **Neuro**. Без загруженной модели Aura не включится и подскажет выбрать модель. Бинд Aura включает и выключает видимое наведение.
9. Мышь немедленно забирает камеру. Возобновление — после настраиваемой паузы; недостающая история заполняется первым известным наблюдением. `.neuro use off` полностью выключает применение.
10. Продолжение: `.neuro train start personal` (или без имени после загрузки). Загружаются веса, AdamW, счётчик и ограниченный replay. `.neuro bots remove` удаляет только созданных системой ботов.

## Команды и настройки

```
.neuro help
.neuro bots spawn [1..8]
.neuro bots remove
.neuro train start [имя]
.neuro train stop
.neuro status
.neuro model list
.neuro model load <имя>
.neuro use on|off
.neuro eval start manual|model [seed]
.neuro eval stop
```

Имена: 1–32 латинские буквы, цифры, `_`, `-`. Новый `train start` с существующим именем продолжает эту модель; другое имя создаёт новую. Короткая/пустая сессия сохраняется, но модель с нулём шагов применять нельзя. Ошибка загрузки сохраняет уже загруженную исправную модель.

В ClickGUI модуль **NeuroTrainer**: скорость ботов (м/с), дистанция, интенсивность стрейфов, радиус демонстраций, learning rate, batch, ёмкость replay, минимум учебных окон, число обновлений за пакет, интервал checkpoints, устройство Auto/GPU/CPU, пауза после мыши, пределы углового шага и независимые переключатели **Автоходьба нейро** / **Автопрыжок нейро**. Включай их после обучения и загрузки. Модель предсказывает направление относительно текущей камеры и прыжок по текущему состоянию и истории ручного боя. Ручные WASD и прыжок сразу имеют приоритет. Автоходьба проверяет столкновение и край пола. В режиме Neuro взмах проходит по обычному таймеру Aura; если прицел в этот момент не пересекает цель, клиент показывает взмах, не отправляет пакет атаки выбранной сущности и записывает контекст как промах. Поэтому выученное наведение может промахиваться при беге, если такие ручные демонстрации есть; частота зависит от того, насколько разнообразно они представлены в обучающих данных. Исторические checkpoints движения v1 загружаются с переносом совместимых весов и replay; AdamW после миграции начинается заново. Если в старой модели нет обученной части движения, переключатели не запускают правила вместо модели; `.neuro status` показывает, что нужны демонстрации ходьбы и прыжков. Нельзя ставить минимум выше ёмкости буфера. Имена модулей всегда английские; подписи настроек есть на пяти языках.

Боты ходят только влево и вправо: по 5 блоков от собственной стартовой точки, с плавным разгоном и торможением на разворотах. Направление дорожки фиксируется по взгляду игрока при создании; движение игрока её не сдвигает. Сближения, отдаления, кругового движения и вертикального смещения нет. При стене или крае пола бот разворачивается раньше. Появляются рядом с ногами игрока, поэтому нужна свободная площадка с полом. В eval направление дорожки фиксировано независимо от взгляда. AntiBot исключает только этих зарегистрированных ботов.

## Модель и синхронизация

Причинная TCN: 37 входов, окно 16 наблюдений, три Conv1d с 24 каналами, kernel=3, dilation=1/2/4, ReLU, Linear 24→2. Всего 6242 обучаемых параметра, эффективная история 15 кадров. Выход — следующий прирост yaw и pitch в градусах за интервал около 50 мс; выход сети умножается на 30.

GRU компактна и пригодна для этой задачи, но здесь TCN выбрана из-за независимых окон, отсутствия переносимого скрытого состояния и возможности точно выполнить её в чистой Java. Обучение — PyTorch/CUDA в отдельном локальном процессе; применение — неизменяемый снимок весов в Java на отдельном потоке CPU. Python не нужен для применения уже сохранённой модели. Межпроцессной задержки в наведении нет. Веса тренера и inference не разделяются: в первой реализации запись/обучение и применение взаимоисключающие.

Семплирование происходит в HEAD локального игрового тика, до автоматических боевых событий. `x(t)` создаётся из уже известных наблюдений; `y(t)` закрывается на следующем наблюдении фактической ручной разницей yaw/pitch. Будущие удары и их исходы не добавляются в ранее созданный x. Углы yaw оборачиваются в [-180,180), pitch ограничивается [-90,90]. Меню, потеря фокуса, FreeCam, смена вида, цель/мир, телепортации и интервалы более 100 мс сбрасывают историю. Интервалы менее 25 мс не создают ускоренные примеры. Это ограничение 20 Гц следует учитывать при очень резких движениях мышью.

Входы делятся на указанные ниже фиксированные масштабы и ограничиваются [-10,10]. Скорости — блоки/секунду; forward/right относительно текущего yaw игрока, up вверх. Нормализация фиксирована и хранится в checkpoint, статистика будущих данных не нужна. `last_d*`, `prev_d*` — последние известные ручные/применённые угловые шаги, в градусах. `ray_*` — координаты точки луча в хитбоксе [-1,1]; при промахе используется проекция луча, ограниченная границами коробки. Центральная угловая ошибка и положение луча позволяют изучать выбранную область прицеливания, без принудительной установки точки в центре.

`previous_attack`, `previous_local_hit`, `previous_miss` — уже наблюдавшиеся события после предыдущего семпла, а не метки следующего удара. По обычным серверным сущностям отправленная ручная атака отмечается `manual_attack_unconfirmed`; подтверждённый серверный урон не выдумывается. По ботам геометрия луча, препятствия, реальная дистанция взаимодействия и cooldown дают `local_hit`/`local_miss`. В журнале также есть смена и потеря цели; интервалы известны по монотонным timestamps и since_attack_s.

Каждый сегмент разбит на блоки по 128 наблюдений. Каждый пятый блок целиком validation; остальные train. Первые четыре позиции каждого временного блока исключены из окон как запас для истории углов и целевого шага. Окна не пересекают границы блоков и не делят соседние входы с другой выборкой. В начале сегмента недостающая история заполнена первым известным наблюдением, одинаково в Python и Java. Это позволяет начать предсказания сразу, не оставляя камеру неподвижной на 0,8 секунды. Изменённая семантика окон отмечена архитектурой causal-tcn-v2; прежние тестовые v1 checkpoints несовместимы. Replay ограничен; train/validation — отдельные буферы. Мини-пакеты случайно выбираются из разных моментов сохранённой тренировки, а не только из последних кадров.

После минимального train-буфера и 32 validation окон каждые восемь новых семплов выполняются forward, SmoothL1 (beta=0.1 в нормированных единицах, около 3°), backward, проверка конечности градиентов, norm clip=10, AdamW. Целевые быстрые движения не обрезаются и отдельного штрафа за плавность нет. Проверяются finite inputs/outputs/loss/gradients/weights. Последние исправные веса и optimizer восстанавливаются после ошибки.

Очереди: Java 512 сообщений, Python 1024, одна выполняемая inference-задача и очередь файловых задач 8. Файлы, обучение, подготовка мини-пакетов, загрузка и расчёт сети выполняются вне игрового потока. Переполнение демонстраций сбрасывает сегмент, чтобы не склеить разрыв; `.neuro status` показывает пропуски. Сбор начинается после сообщения «Тренер готов»: до готовности Python/CUDA примеры и события не ставятся в очередь. Статус показывает этап загрузки и путь Python; `trainer-stderr.log` содержит время этапов и traceback при задержке импорта более 60 секунд. Общий предел запуска — 180 секунд. Отмена до готовности завершает процесс без ложного сообщения о сохранении; существующие checkpoint остаются на диске. При выходе из мира сбор/камера прекращаются, боты удаляются, готовый тренер получает stop и сохраняет очередь. Завершение процесса контролируется без ожидания на игровом потоке; JVM shutdown даёт ограниченное время сохранения.

Предсказание поступает в ближайший render frame и интерполируется за 50 мс; остаток предыдущего поворота сохраняется, если следующий результат пришёл раньше завершения. Проверяется сохранение суммарного yaw и pitch при 20/30/60/144/240 FPS. Реальный yaw/pitch и боевое направление совпадают. В NeuroTrainer есть независимые «Множитель yaw нейро» и «Множитель pitch нейро» (0.25–3, исходно 1): они масштабируют выходы существующей модели перед ограничением шага, но не доучивают веса и не улучшают сами validation-метрики. `.neuro status` показывает оба выхода модели, множители, число принятых/устаревших результатов и паузу мыши. Устаревшие результаты с другой целью/миром/режимом отбрасываются. При препятствии или потере цели камера останавливается. Никакая скрытая ротация, аналитическое доведение или случайный шум не подмешиваются. Мышь сбрасывает текущий шаг ещё до native `player.turn`.

Диагностика сохранённой модели без изменения весов: `.neuro-runtime\Scripts\python.exe tools/inspect_neuro.py test1`. Она сравнивает ручные и предсказанные изменения отдельно по yaw/pitch на сохранённых train/validation окнах и пишет только агрегированные статистики в `build/neuro-check/inspection-test1.json`. Это проверка записанных данных; она не доказывает качество сопровождения в игровом замкнутом цикле.

## Файлы и восстановление

Корень — `pizzadlc/neuro` относительно рабочей папки клиента (обычно `run/pizzadlc/neuro`).

- `models/<имя>/current.json`: атомарный указатель на поколение, SHA-256 обоих файлов.
- `g-*.pt`: веса, архитектура/схема/масштабы, AdamW, replay, шаги, метрики, время.
- `g-*.json`: переносимый снимок для Java, те же схема и нормализация.
- `previous.json`: предыдущая проверенная версия. Сохраняются два поколения; запись временных файлов, fsync и replace защищают старую модель при прерывании. Если текущая версия повреждена, загрузчик пробует предыдущую; при полной несовместимости выдаёт ошибку.
- `demonstrations/*.jsonl`: нормированные ручные наблюдения/метки и события, до 8 файлов по ~25 МБ. Никаких внешних отправок.
- `evaluations/*.json`: результаты сравнения.
- `trainer-stderr.log`: диагностика локального Python. `.status` показывает конкретную ошибку.

Нельзя считать train loss единственным критерием. `.status` показывает validation MAE в градусах и два baseline: нулевое движение и повтор последнего углового шага. Низкий loss на синтетике не означает сходства с человеком.

## Сравнение в замкнутом цикле

На одной площадке, из одной позиции, с одинаковыми настройками:

```
.neuro eval start manual 731
# 30–60 секунд ручного сопровождения
.neuro eval stop
# выбери Rotation Mode = Neuro и включи Attack Aura её обычным биндом
.neuro eval start model 731
# тот же отрезок времени; не двигай мышь, если измеряешь автоматическое наведение
.neuro eval stop
.neuro use off
```

Одинаковый seed даёт одинаковый сценарий одного бота на фиксированной дорожке ±5 блоков, независимо от yaw в момент запуска. Повторяй из той же позиции: движение самого игрока и столкновения могут изменить наблюдения. В отчёте — seed/параметры/начало, доля удержания луча на хитбоксе (в радиусе демонстраций), ошибка относительно центра, средние скорость, модуль ускорения и jerk камеры, средняя и p95 задержка вычисления сети, накладные расходы Neuro на игровом тике и render frame. Сравни одинаковую длительность и поведение при смене дистанции/направления. Это наблюдение настоящего feedback loop камеры, а не только проигрывание записанных входов. Настоящее сходство со стилем пользователя пока не измерено: для этого нужны его демонстрации и оба отчёта.

## Установка backend на другом компьютере

На этой машине реально проверены Windows, Python 3.14.6, RTX 5050 8 ГБ, драйвер 616.64, PyTorch 2.14.1+cu130. Общесистемный torch остался CPU; GPU-пакет установлен только в `.neuro-runtime`. Команда Auto выполняет настоящий CUDA backward probe; при недоступности сообщает причину и использует CPU. GPU принудительно выдаёт ошибку вместо скрытого перехода на CPU. CPU также выбирается явно в NeuroTrainer.

Нужны Python и совместимые PyTorch + numpy. Пример для этой конфигурации (терминал в корне проекта):

```powershell
python -m venv --system-site-packages .neuro-runtime
.\.neuro-runtime\Scripts\python.exe -m pip install numpy
.\.neuro-runtime\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu130
```

При другой ОС/видеокарте выбирай совместимую официальную сборку PyTorch. Поиск Python: JVM-свойство `-Dpizzadlc.neuro.python=<полный путь>`, затем `.neuro-runtime/Scripts/python.exe` в рабочей папке/двух родительских папках, затем `python` из PATH. JSON настроек передаётся файлом, чтобы избежать потери кавычек ProcessBuilder на Windows. Применение сохранённой модели не зависит от наличия CUDA/Python.

## Автоматические проверки

```powershell
.\.neuro-runtime\Scripts\python.exe tools/verify_neuro.py
.\gradlew.bat --offline verifyNeuro -PneuroProcessCheck
.\gradlew.bat --offline build
```

Python проверяет реальное обучение и сравнение с baseline на **синтетике**, раздельные временные блоки, bounded replay, пустую/короткую сессию, NaN, checkpoint/optimizer continuation, восстановление предыдущего поколения, subprocess и недоступный GPU. Создаёт только отдельные тестовые модели в `build/neuro-check`.

Java проверяет точное совпадение с PyTorch, схему/checksum, угловые границы, команды/ограничения, воспроизводимое движение ботов, блокировку боевых модулей, реальную камеру и боевые углы, feedback loop с обученной синтетической моделью, мышь, препятствия, выход из мира. Дополнительный `-PneuroProcessCheck` прогоняет нативные наблюдения через настоящий Python-процесс на доступном устройстве, проверяет обновления, остановку/загрузку и продолжение обучения. Тестовые движения не являются демонстрациями пользователя.


Отдельный полный клиентский тест запускается `.\gradlew.bat --offline runClient -PneuroClientTest`. Он собирает отдельный тестовый мод, создаёт изолированный встроенный мир в `build/neuro-client-test/game`, проверяет настоящие сущности ботов, локальный native attack, отсутствие ботов на сервере, выбор цели, движение и удаление/отключение; сохраняет screenshot. Тестовый мод не включён в обычный JAR.

Он использует **искусственного демонстратора только в тесте**, пишет отдельную модель `synthetic_live_*` в изолированную папку, проверяет GPU updates, save/load, применение настоящей камеры и продолжение AdamW. Такая тестовая модель не включается в обычный клиент и не считается стилем пользователя. GPU-проверки следует запускать последовательно: несколько отдельных CUDA-процессов вместе с Minecraft могут исчерпать память.


## Проверенные результаты на этой машине

16.10.2026, Windows / Minecraft 26.2 / RTX 5050 / PyTorch 2.14.1+cu130:

- В настоящем игровом мире: 998 **искусственных** демонстраций, 424 GPU updates; последний Δвесов L2=0.01348, norm градиента=0.00766. После сохранения и загрузки камера двигалась от первого лица. Проверены мышь, продолжение AdamW 424→448, локальные попадания, отсутствие ботов на сервере, пол, движение и удаление при отключении.
- Validation MAE=0.224°, baseline нулевого движения=0.532°, повтор последнего шага=0.030°. Сеть пока уступает persistence на этом плавном искусственном сценарии. Снижение loss не выдаётся за улучшение над обоими baseline.
- Два 200-тиковых замкнутых прогона с разными траекториями дали 96/200 и 23/200 удержания луча на хитбоксе. Это проверка работы камеры и сигнал об ограниченной обобщающей способности короткой тестовой тренировки. Траектории этих интеграционных прогонов не являются парным сравнением по одному seed; для такого сравнения используйте eval с одинаковым seed.
- Отдельная синтетическая GPU-проверка выполнила 408 updates и проверила optimizer resume, повреждение checkpoint, NaN, раздельный holdout и CPU subprocess. Эти измерения не описывают личный стиль пользователя.
- Нейромодель движения учится на ручном WASD, прыжке и спринте. Она хранит отдельные веса в том же checkpoint; старые checkpoints ротации остаются загружаемыми с пустой частью движения. В проверке применяются те же temporal holdout и сравнение с baseline стоять; синтетический результат не доказывает пригодность личного управления.
- Совпадение Python/Java проверяется с допуском 0.0002°. Эталон `src/verification/resources/neuro-parity.json` получен настоящим PyTorch и доступен без установленного Python при обычном Java build.

Личных ручных демонстраций пользователя в автоматической проверке не было. Сходство с его стилем, качество длительного боя и влияние на FPS в его обычной конфигурации ещё не измерены. Сравнение качества TCN и GRU на таких данных не проводилось. Человеческая неотличимость или обход античита не заявляются.

Машиночитаемая запись: `build/neuro-check/live-result.json`. Кадры игрового теста: `build/neuro-client-test/game/screenshots`. Тестовые модели перенесены в `build/neuro-client-test/game/pizzadlc/neuro` и не подставляются как личная модель. Для последующих тестов рабочая папка задаётся через `loom.runs.client.runDir`, поскольку одного JavaExec workingDir недостаточно.

### Остановка с накопленной очередью

После `.neuro train stop` Java сначала отправляет управляющее сообщение `drain`. Python завершает текущий пакет оптимизатора, затем только добавляет оставшиеся принятые демонстрации в ограниченный replay и журнал; дополнительные обновления и промежуточные checkpoints на очереди не выполняются. По сообщению `stop` один раз сохраняются веса, optimizer и replay. Последние демонстрации доступны для следующего продолжения обучения. Финальное сохранение ограничено 120 секундами, весь путь остановки — 180 секундами; зависший процесс по-прежнему завершается. Проверка: `.neuro-runtime/Scripts/python.exe tools/verify_neuro_stop.py`. Она проверяет очередь из 1000 примеров, контрольные суммы, продолжение и отсутствие лишних шагов оптимизатора при остановке.
